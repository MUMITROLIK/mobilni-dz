# 07. Гра на виживання (.NET MAUI)

Піксельна міні-гра на виживання: голод, енергія, здоров'я, рівні, локації, збір ресурсів, крафт інструментів і окремі анімовані сцени дій.

## Що зроблено (за завданням з 15.10)

**Екрани** (між усіма є переходи вперед і назад)
- **Головне меню**: продовжити, нова гра, завантажити, зберегти, налаштування, вийти.
- **Налаштування**: повзунки музики і звуків (поки заглушки), перемикач підказок.
- **Табір (головний екран героя)**: смуги здоров'я, ситості й енергії, рівень, досвід, день, дії «Досліджувати», «Інвентар», «Спати», «Поїсти».
- **Дослідження локацій**: ліс, пустеля, тундра, печера. Кожна відкривається з певного рівня героя.
- **Локація**: список дій збору ресурсів із витратою енергії.
- **Інвентар**: список ресурсів (їжу можна з'їсти) і крафт інструментів (сокира, кирка, вудка дають +1 до видобутку).

**Фарм ресурсів за часом (друга частина завдання)**
- Кнопка запускає збір на **10 секунд**, під час якого герой зайнятий. Є змінні: енергія, досвід, випадкова кількість ресурсу.

**Окрема сцена дії** (власна ідея, щоб було цікавіше)
- Збір відкриває сцену: герой замахується інструментом, ціль трясеться, летять уламки, дерево падає, потім з'являється нагорода. Є також сцена сну біля вогнища.

## Як запустити

```bash
dotnet workload install maui-windows maui-android
dotnet run -f net8.0-windows10.0.19041.0
```

## Структура

- `Services/GameState.cs` — вся логіка: характеристики, час, збір, їжа, крафт, збереження в файл.
- `Models/Catalog.cs` — дані гри: ресурси, локації, дії, інструменти (щоб додати нову локацію, достатньо додати рядок).
- `Pages/` — екрани (`MenuPage`, `HomePage`, `LocationsPage`, `LocationPage`, `ScenePage`, `InventoryPage`, `SettingsPage`).
- `Controls/` — `HudBar` (панель стану), `PixelBar` (смуга), `Backdrop` (живий фон), `PixelDialog`.
- `Services/Fx.cs` — спільні анімації. `tools/GenerateSprites.ps1` — генератор усіх картинок.

## Як це працює (коротко)

1. **Один спільний стан.** `GameState.Current` живе весь час роботи застосунку, тому прогрес не губиться під час переходів між екранами. Екрани підписуються на подію `Changed` і самі перемальовуються.
2. **Ігровий час.** Таймер раз на 100 мс викликає `Tick(dt)`. `dt` рахується за справжнім годинником (`Stopwatch`), тому 10 секунд збору завжди дорівнюють 10 справжнім секундам, навіть якщо кадр затримався.
3. **Збір ресурсів.** `StartTask` одразу списує енергію і створює `ActiveTask`. У кожному тіку `Remaining` зменшується, а в кінці `FinishTask` додає випадкову кількість ресурсу, досвід і запам'ятовує підсумок для екрана нагороди.
4. **Дані замість копіпасти.** Локації й дії описані списком у `Catalog`, екрани будуються з нього в циклі.
5. **Навігація.** Екрани зареєстровані в `AppShell.xaml.cs` через `Routing.RegisterRoute`; параметри (`place`, `action`) передаються в рядку маршруту і потрапляють у сторінку через `[QueryProperty]`.
6. **Анімації.** Смуги плавно «доганяють» значення таймером ~60 разів на секунду. Уламки летять по параболі (формула у `Animation`). Зірки і хмаринки фону на Windows віддані композитору WinUI (відеопідсистемі), тому не навантажують процесор.
7. **Збереження.** `SaveData` серіалізується в JSON (`survival-save.json`) у приватній папці застосунку.
